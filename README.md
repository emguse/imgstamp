# imgstamp

ディレクトリ内の TIFF・PNG・JPEG に画像や1行の文字を重ね、入力ファイルごとに印刷用 PDF を作成する CLI です。マルチページ TIFF のページ構成を維持し、ページのピクセル寸法から出力用紙を判定します。

## ビルド

Go 1.27.1 以降で、リポジトリのルートから実行します。

Go モジュールパスは `github.com/emguse/imgstamp` です。実行ファイル名は `imgstamp` です。

```sh
go build -o bin/imgstamp ./cmd/imgstamp
```

Windows では出力名を `bin/imgstamp.exe` にしてください。実行時に Python や外部の画像変換ソフトは不要です。

## バージョン管理

本体の版番号は Git タグで管理し、配布ビルドには同じ番号を埋め込みます。`v0.1.0` は正式版です。`v0.1.0-rc.1` と `v0.1.0-rc.2` はリリース候補でした。通常の開発ビルドの `--version` は `imgstamp dev` を表示します。[リリース手順](docs/releases.md)と[変更履歴](CHANGELOG.md)を参照してください。

## 使用方法

1. [設定例](examples/stamp.toml)をコピーします。
2. 用意した透過 PNG のパス、文字列、フォント、記入欄、用紙判定ルールを設定します。画像パスは設定ファイルの場所を基準とします。
3. 次のコマンドで利用可能なフォント名を確認し、入力と独立した出力フォルダを指定して実行します。

```sh
bin/imgstamp fonts
bin/imgstamp --config stamp.toml --input ./drawings --output ./stamped
```

フォントには一覧のフルネームを指定します。TTF・OTF・TTC・OTC の読み取り可能なフォントを OS のユーザー／システムフォントフォルダから探索します。同名のフォントはユーザーフォルダを優先します。フォントの自動ダウンロードや欠落文字の代替表示は行いません。

- 対象は入力フォルダ直下の通常ファイルです。サブフォルダ、シンボリックリンク、印影画像自身を除外します。
- `drawing.tif` は `drawing.tif.pdf` になります。既存出力はスキップし、元画像を変更しません。
- 1ページでも失敗した入力ファイルは PDF を出力せず、次の入力へ進みます。`processed` は PDF 完成前のページ進捗で、ファイルの成功は `success` で確認します。
- 画像のみの場合は `[stamp.text]` を削除します。文字のみの場合は `stamp.image` と `stamp.width_px` を削除し、記入欄の原点を `(0, 0)` にします。
- 中断は Ctrl+C。完了済み出力を残し、処理中の未完成 PDF は削除します。
- 終了コードは `0`: 失敗なし、`1`: 個別ファイル失敗、`2`: 設定不備／開始不能、`130`: 中断です。

設定では用紙別余白を指定でき、文字は `rotation_deg` で0/90/180/270度に回転できます。ページ上限は3億画素です。詳細は[設計書](docs/design.md)を参照してください。例示された300dpi換算の寸法は実測値ではありません。

## 検証と制限

```sh
go test ./...
go test -race ./...
go vet ./...
```

用紙判定、配置、透明度、圧縮方式、複数ページ、白黒解釈、途中失敗時の削除、上書き競合を自動テストします。PDF は合成した8bit/channelの画像を可逆圧縮で格納し、テキスト検索や元画像のメタデータ保持は提供しません。

- 出力の確定には同一フォルダ内のハードリンクを使用します。対応しないファイルシステム（例: FAT/exFAT）では安全にエラーになります。ローカルの APFS／NTFS 等の出力先を使用してください。
- BigTIFF、CCITT Group 3 の2次元符号化・非圧縮モード、Group 4 の非圧縮モードは未対応です。
- macOS ARM64 で実行・日本語描画・PDF レンダリングを確認しています。利用者によりWindows実機と実画像での正式版動作も確認済みです。
- 紙への印刷結果と最大常駐メモリは未検証です。3億画素上限はメモリ使用量を保証するものではありません。
