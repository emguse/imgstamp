# imgstamp 設計書

状態: **v0.2.0 正式版リリース予定**。利用者によりWindows実機でA1図面の縮小を含む動作確認済み。8GB搭載機で処理は完了したが時間を要した。メモリ表示は処理中に8GB超との報告があるものの、表示項目が不明なため最大常駐メモリは未検証。紙への印刷結果も未検証として扱う。操作方法と現在の制限は [README](../README.md) を参照する。

## 目的・対応範囲

- 個人向け CLI として、Windows x64・macOS ARM64 用の実行ファイルを配布する。
- 指定フォルダ直下の TIFF・マルチページ TIFF・PNG・JPEG を処理する。
- 入力ファイルごとに1つの PDF を別フォルダへ出力し、全ページの順序とページ数を維持する。
- 通常はグレースケールとし、カラー出力も設定で選択できる。
- 元図面サイズや縮尺の復元・保証は行わない。図面を歪めず、指定用紙に配置して読みやすく出力する。
- 初期対象外: UI、再帰探索、上書き、直接印刷、BigTIFF、日付等の文字列への自動埋め込み、任意個数のスタンプ配置。

モジュールは `github.com/emguse/imgstamp`、`go.mod` の Go 宣言は `1.27.1`。CLI、実装パッケージ、自動テスト、設定例を含む。

## CLI と設定

```text
imgstamp --config stamp.toml --input ./drawings --output ./stamped
imgstamp fonts
imgstamp --version
```

`fonts` は指定可能な OS フォント名を一覧表示する。用紙判定とスタンプ設定は TOML に保存する。縮小モードは `--shrink`、追記文字列は `--text VALUE` で実行単位に指定できる。`--text` は設定済みの `stamp.text.value` と同じ Unicode 文字数に限り、改行・制御文字や記入欄からのはみ出しは拒否する。

設定例は [examples/stamp.toml](../examples/stamp.toml) を参照する。設定中の画像パスは設定ファイルの場所、CLI の相対パスは実行時の作業ディレクトリを基準とする。

### 用紙判定と出力

| キー | 内容・初期値 |
| --- | --- |
| `output.color_mode` | `grayscale`（初期値）または `color` |
| `paper_detection.tolerance_percent` | 共通許容誤差。初期値 `2.0`、範囲0〜10% |
| `paper_detection.rules[].name` | ルールの識別名 |
| `paper_detection.rules[].short_px` | 基準短辺のピクセル数 |
| `paper_detection.rules[].long_px` | 基準長辺のピクセル数 |
| `paper_detection.rules[].paper` | 出力用紙。`A1`・`A2`・`A3`・`A4` |
| `paper_detection.rules[].tolerance_percent` | 任意。共通許容誤差を上書き。範囲0〜10% |

少なくとも1つのルールを指定する。同じ用紙へ対応するルールを複数登録できる。許容誤差2%は変更可能な初期値であり、実データで検証した値ではない。

### スタンプ

| キー | 内容・初期値 |
| --- | --- |
| `stamp.image` | 透過 PNG のパス。画像使用時に指定 |
| `stamp.width_px` | 任意。印影の幅。省略時は原寸。指定時は縦横比を維持 |
| `stamp.position` | 初期値 `bottom-right`。9か所の基準位置 |
| `stamp.margin_x_px` / `stamp.margin_y_px` | 横・縦の余白。各16pxが初期値 |
| `stamp.paper_margins.<paper>.margin_x_px` / `margin_y_px` | 用紙別の任意の余白上書き。未指定の軸は共通余白を使用 |
| `stamp.background_opacity` | 印影全体の白背景の不透明度。初期値 `0.5` |
| `stamp.image_opacity` | 印影の不透明度。初期値 `0.8` |
| `stamp.text.value` | 全入力・全ページ共通の固定文字列 |
| `stamp.text.font` | OS 上のフォント名。文字使用時に必須 |
| `stamp.text.size_px` | 文字サイズ。文字使用時に必須 |
| `stamp.text.rotation_deg` | 時計回りの回転角度。`0`（初期値）・`90`・`180`・`270` |
| `stamp.text.color` | `#RRGGBB`。初期値 `#000000` |
| `stamp.text.opacity` | 文字の不透明度。初期値 `0.8` |
| `stamp.text.box_x_px` / `stamp.text.box_y_px` | 記入欄左上の座標 |
| `stamp.text.box_width_px` / `stamp.text.box_height_px` | 記入欄の幅・高さ |

不透明度は0〜1（0は透明、1は不透明）。初期値は試し刷り用の仮値であり、読みやすさや印刷コストへの効果を保証する値ではない。

位置は `top-left`・`top-center`・`top-right`・`center-left`・`center`・`center-right`・`bottom-left`・`bottom-center`・`bottom-right`。中央の軸では対応する余白を適用しない。

用紙別余白は `[stamp.paper_margins.A1]` のようなテーブルで指定する。横・縦の一方だけでも上書きでき、省略した軸は `stamp.margin_x_px` / `stamp.margin_y_px` を使う。用紙名は A1〜A4。

設定例の余白24px、文字サイズ32px、記入欄寸法は調整用の例示値であり、省略時の初期値ではない。画像とフォントは同梱せず、利用環境に合わせて指定する。

## 用紙サイズの判定

1. ページの向き情報を反映し、幅・高さのピクセル数を取得する。
2. 短辺と長辺を各ルールと照合する。両辺が次の条件を満たす場合に一致とする。

```text
abs(実寸px − 基準px) / 基準px ≤ tolerance_percent / 100
```

3. ちょうど1つのルールに一致した場合、その出力用紙を採用する。幅・高さから縦横を判定する。
4. 未一致・複数一致はページのエラー。同じ用紙を指定する複数ルールへの一致もエラーとし、最も近いルールへの自動割り当てはしない。

対応表は縮小前の画像の用紙を指定する。通常モードでは判定用紙が出力用紙となる。`--shrink` を指定した場合、A1・A2 は A3、A3 は A4 を出力用紙とする。A4 は縮小しない。

縮小倍率は判定した元用紙と出力用紙の物理寸法比から求め、図面画像だけを縦横比を保って縮小する。縮小後の画像へ元と同じピクセル寸法のスタンプを合成するため、縮小処理によってスタンプ自体は小さくならない。スタンプの余白・配置設定値も縮小せず、そのまま適用する。したがって縮小前に比べ用紙に対する余白の割合や配置の見え方が変わる。

以下は設定例の300dpi換算の仮値。`mm / 25.4 × 300` を四捨五入した値であり、実測値ではない。実データ入手後に変更する。

| 用紙 | 基準短辺px | 基準長辺px | PDF の縦向き寸法mm |
| --- | ---: | ---: | --- |
| A1 | 7016 | 9933 | 594 × 841 |
| A2 | 4961 | 7016 | 420 × 594 |
| A3 | 3508 | 4961 | 297 × 420 |
| A4 | 2480 | 3508 | 210 × 297 |

入力の DPI は判定に使用せず、欠落・不正でもそれ自体をエラーにしない。DPI から用紙を推定する補完処理は設けない。

## スタンプの合成

- 透過 PNG をひな形にし、印影の枠内へ横書き1行の文字を左揃え・上下中央で描画する。
- `rotation_deg` が0以外の場合、文字を指定角度で時計回りに回転し、回転後の文字を記入欄の中央に配置する。記入欄寸法は回転後の文字を収める寸法とし、収まらない場合は事前検証でエラーにする。
- 記入欄はサイズ変更後の印影左上を基準としたピクセル座標。印影を変更した場合、記入欄も設定で調整する。
- 画像のみ、文字のみ、両方を使用できる。少なくとも片方を指定する。文字のみの場合は記入欄をスタンプ全体の領域とし、欄の原点を `(0, 0)` とする。
- 描画順は「図面 → 印影全体の矩形を覆う半透明白背景 → 印影 → 文字」。各不透明度を独立して適用する。
- `grayscale` では図面とスタンプの両方をグレースケール化する。`color` では色を保持する。
- フォント不在、必要文字の欠落、記入欄からの文字のはみ出しは事前検証でエラー。自動置換・折り返し・縮小・切り落としはしない。
- スタンプがページに収まらない場合はページのエラーとする。
- 合成は PDF 配置前の画像上でピクセル単位で行う。`--shrink` では図面画像を先に縮小し、スタンプは設定済みピクセル寸法を保ってから合成する。実際の印刷寸法は入力用紙ルールの画素寸法とPDF配置に依存する。

## PDF 出力と印刷

- 入力ごとに1つの PDF を作成し、TIFF のページ順とページ数を維持する。
- 判定した用紙と向きに応じて PDF の各ページ寸法を設定する。
- 合成済み画像を縦横比を維持して用紙内へ最大サイズで中央配置する。余りは白余白とし、画像を歪めたり切り取ったりしない。
- 元画像の画素数を減らさず、可逆圧縮で PDF に格納する。JPEG への再圧縮は行わない。
- 出力名は `drawing.tif.pdf` のように入力拡張子を含め、異なる入力形式の同名ファイルを区別する。
- 印刷は PDF ビューアーから行う。PDF のページサイズに対応する用紙と縦横を確認し、「実際のサイズ／100%」を基本に試し刷りする。直接印刷機能は持たない。
- 試し刷りでは元図面の縮尺ではなく、図面が欠けていないこと、印影と文字の可読性、下地の線の見え方を確認する。

## バッチ処理・失敗時の動作

1. 設定、フォント、印影、入出力フォルダを検証する。未知のキー、不正な寸法・不透明度・許容誤差は開始前に検出する。CLI 文字列上書きは設定文字列と同じ Unicode 文字数であることも検証する。
2. 入出力が同一・包含関係にある指定は拒否する。サブフォルダ、シンボリックリンク、スタンプ画像自身を対象外とする。
3. ファイル名順・ページ順に逐次処理する。全ページの展開画像をメモリに保持しない。
4. 既存出力は入力ファイル単位でスキップする。設定変更後も自動更新せず、再生成には新しい出力フォルダを使う。
5. PDF は一時ファイルで完成させてから、既存ファイルを置換しない方式で確定する。

**1ページでも失敗した場合、その入力ファイルの PDF は出力しない。** ページ欠落や未押印ページを含む完成品は作らない。次の入力ファイルは継続する。

失敗・中断時は未完成の一時ファイルを削除し、完成済み PDF は保持する。元画像と既存 PDF は上書きしない。

ファイル名・ページ番号・判定した用紙・成功／スキップ／失敗と最終集計を表示する。ページ画像の上限は1ページ3億画素。印影・文字欄の上限は1億画素のまま。厳密なメモリ使用量の保証ではなく、レビュー・実測で見直す制限とする。

| 終了コード | 意味 |
| --- | --- |
| `0` | 失敗なし。対象ゼロは警告付き成功 |
| `1` | 個別ファイルの失敗あり |
| `2` | 設定不備・開始不能 |
| `130` | 中断 |

## 実装上の責務

設定読み込み、用紙判定、ページ読み込み、フォント解決、スタンプ合成、PDF 出力、バッチ制御を分離する。CLI は入力と結果表示・終了コードを担当する。

エントリーポイントは `cmd/imgstamp/`、実装パッケージは必要に応じて `internal/` に置く。テストはソースの隣、画像フィクスチャは各パッケージの `testdata/` に置く。実装を伴わない空のディレクトリは作成しない。

利用者側に Python や外部の画像変換ソフトのインストールを要求しない。TOML は `go-toml/v2`、TIFF は `hhrutter/tiff`、フォントと画像処理は `golang.org/x/image` を使用する。PDF はページ単位で画像ストリームを書き出し、全ページの展開画像を保持しない。

## 検証条件

- 用紙判定: 縦横入れ替え、許容誤差の境界、片辺だけ不一致、未一致、複数一致、同じ用紙への複数ルール。
- TIFF: 単一・複数ページ、寸法と向きの混在、無圧縮・CCITT Group 3/4・LZW・Deflate。BigTIFF は初期対象外。
- 合成: 日本語、記入欄の位置、0/90/180/270度回転と回転後のはみ出し、用紙別余白と共通余白へのフォールバック、9か所の配置、不透明度、グレースケール／カラー、画像のみ／文字のみ。
- PDF: ページ数、順序、用紙寸法、縦横比、白余白。レンダリングで枠線と文字、細線・密集線に重なった箇所を確認する。
- バッチ: 破損ページ、既存出力、書き込み失敗、中断、日本語・空白を含むパス。失敗したファイルの不完全な PDF が残らないこと。
- 配布: Windows x64・macOS ARM64 で実行とフォント探索を検証する。A1・600dpi 相当の連続処理で、展開画像のメモリ使用量がページ数に比例して増えないことを確認する。

Windows実機と実画像での動作は利用者により確認済み。**紙への印刷結果と最大常駐メモリは未検証**として扱い、実施した検証と分けて記録する。

## 現在の実装上の制限

- TIFF の CCITT Group 3 は1次元符号化を対象とし、2次元符号化と非圧縮モード、Group 4 の非圧縮モードはエラーとする。
- 出力の確定はハードリンクによる非置換方式とする。非対応のファイルシステムではエラーとし、既存出力を置換する方式へ切り替えない。
- フォント一覧は OS のフォントフォルダにある読み取り可能な TTF・OTF・TTC・OTC のフルネーム。読み取れない形式や未導入のフォントは対象外。
- PDF 内の画像は8bit/channel。検索可能なテキスト、ICC 色管理、元画像のメタデータ保持は対象外。
- macOS ARM64 で合成画像による実行とレンダリング、Windows x64 のクロスビルドを確認した。Windows実機と実画像での動作は利用者が確認済み。紙の印刷結果は未検証。
- 最大常駐メモリの計測は保留。複数ページの変換成功を、メモリ使用量の検証完了とは扱わない。
